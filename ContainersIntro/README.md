***Теория***

**Контейнеризация** — технология изоляции приложения (процесса) и его зависимостей в отдельную сущность, контейнер. Её преимущества: портативность, экономное использование ресурсов, быстрое развёртывание, изоляция приложений и удобство разработки (каждый пишет свой «контейнер»).

1. **Что такое изоляция**

Главная мысль лекции: контейнер — это обычный процесс. Его «отделяют» от остальной системы два механизма ядра:
cgroups ограничивают, сколько ресурсов процесс может потратить (CPU, RAM, I/O). В современных дистрибутивах используется cgroups v2.
namespaces ограничивают, что процесс видит.

2. **Linux Namespaces**

Namespace — это абстракция над системным ресурсом. Для каждого контейнера создаются свои неймспейсы и cgroups, то есть для процесса строится своего рода «матрица». Девиз лекции: «Чего не видно — того не существует».

**Виды неймспейсов:**

Namespace	Что изолирует
- PID	 - Дерево процессов. В новом неймспейсе свой PID 1. Процессы не видят процессы снаружи и не могут на них влиять. У одного процесса два PID: снаружи, например, 8, внутри 1

- NET	 - Сетевой стек: интерфейсы, маршруты, правила iptables. Неймспейсы соединяются парой виртуальных интерфейсов (veth) через мост (bridge). Трафик извне попадает в контейнер через NAT в iptables

- MNT	- Точки монтирования. Процессу дают минимальную корневую директорию и монтируют её как /, по аналогии с chroot

- UTS	- Имя хоста (hostname) и domainname

- IPC - Семафоры, очереди сообщений, разделяемая память

- USER	- UID и GID. Внутри процесс может быть root (UID 0), а снаружи оставаться обычным пользователем. Соответствие UID называется маппингом (/proc/self/uid_map)

- CGROUP - Представление иерархии cgroups (с ядра 4.6)

- TIME - Системные часы (с ядра 5.6)

**Docker**

Стек безопасности контейнера снизу вверх: инфраструктура → namespaces → cgroups (CPU, RAM, storage, network) → seccomp (фильтр системных вызовов) → SELinux/AppArmor. Добавляются ещё capabilities, то есть дробление прав root. Для самостоятельного изучения дана ссылка на лекцию Яндекса по безопасности ОС.

Docker — платформа для разработки, доставки и запуска контейнерных приложений. Основные компоненты:
Docker Engine запускает контейнеры и управляет ими.
Image (образ) — шаблон, из которого создаётся контейнер.
Registry (реестр) хранит и распространяет образы, например Docker Hub.
Container — запущенный экземпляр образа.
Dockerfile — текстовый файл с инструкциями для сборки образа.

 2) Неймспейс для PID.

- `sudo unshare --pid --fork --mount-proc bash`

Здесь три флага:

а) --pid создаёт новый PID-неймспейс с отдельной нумерацией процессов.
б) --fork делает так, чтобы bash запустился как новый процесс и стал первым в неймспейсе, то есть получил PID 1. Без этого флага bash остался бы в старой нумерации, и неймспейс сломался бы при первой же команде.
в) --mount-proc заново монтирует каталог /proc. Команда ps берёт список процессов именно оттуда. Без этого флага ps читал бы хостовый /proc и показывал бы все процессы ВМ, хотя изоляция на самом деле есть. Этот флаг автоматически создаёт и новый mount-неймспейс, чтобы не испортить /proc у хоста.

Изменились три строки:

mnt — новый mount-неймспейс, его создал флаг --mount-proc.

3) Неймспейс для UID.

`sudo unshare --user --map-root-user bash`

Два флага:
--user создаёт новый user-неймспейс со своей таблицей пользователей. Сразу после создания она пустая.
--map-root-user заполняет таблицу: «UID 0 (root) внутри = мой UID 1000 снаружи». То же делается для групп.

4) Неймспейс для MNT.

`sudo unshare --mount --propagation private bash`

--mount создаёт новый mount-неймспейс. Ядро копирует в него текущую таблицу монтирований хоста.
--propagation private запрещает монтированиям «перетекать» между неймспейсами. В Ubuntu systemd делает корень «общим» (shared): без этого флага то, что вы смонтируете внутри, появилось бы и на хосте, и изоляции бы не было.

***Задание 1***

**SUDO**

позволяет пользователю произвести действие под рутом, не входя под ним. Настраивается в /etc/sudoers:

![alt text](<screenshots/Screenshot From 2026-09-14 20-44-30.png>)

Синтаксис строки `root ALL=(ALL:ALL) ALL` означает:

*root - кому
*ALL - на каких хостах
*(ALL:ALL) - от имени каких пользователей и групп
*ALL - какие команды может выполнять без ввода пароля

Действия пишутся в `/var/log/auth.log`


**SUID & SGID**

-это спецбиты на исполняемом файле. При запуске:
*SUID - программа выполняется с правами владельца файла, а не того, кто ее запустил(то есть, он позволяет запускать исполняемый файл с правами владельца этого файла).
*SGID - с правами группы файла(а на каталоге - новые файлы наследуют группу каталога, аналогичен suid, но он для групп).

Пример suid:

![alt text](<screenshots/Screenshot From 2026-09-14 21-24-02.png>)

Обычному пользователю нужно менять свой пароль, а это запись в 
/etc/shadow, куда пишет только root. s в части прав владельца означает как раз наличие suid.

Принцип работы:
*Sudo работает через конфигурационный файл /etc/sudoers и логируется в /var/log/auth.log
*SUID/SGID устанавливаются через chmod и видны в правах доступа как буква 's'


**Мисконфигурации и их последствия**

-Основные типы мисконфигураций:
*Чтение — доступ к конфиденциальным файлам (/etc/shadow, ключи)
*Запись — изменение критических конфигурационных файлов
*Исполнение — получение shell с повышенными привилегиями

-Примеры уязвимостей
*Неправильно настроенные права в sudoers, дающие слишком широкие возможности
*SUID на опасных утилитах (например, на редакторах или архиваторах)
*SGID на директориях с возможностью записи для неавторизованных пользователей

- команда `sudo cat /etc/shadow > ~/shadow_copy` копирует оригинальный /etc/shadow  домашнюю директорию для дальнейшего рекдактирования без sudo.

- команда `grep "^root:" ~/shadow_modified` — проверяем, что хэш заменился корректно и поля разделены двоеточиями.
